# A：Agent 动作投机——统一对比表

更新时间：2026-08-03

## 1. 方法机制对比

| 论文 | 时间 | 投机对象 | 投机窗口 | Speculator 来源 | 粒度/控制 | 验证与恢复 | 严格无损性 |
|---|---:|---|---|---|---|---|---|
| Speculative Actions | 2025/2026 | 下一动作、API 调用及其前置观测 | 当前 Actor/API/环境尚未返回 | 外部快速模型、低 reasoning 模型或规则 | 单步多分支；v2 扩展多步与选择性启动 | 权威 Actor 产生真实轨迹；命中复用，未命中丢弃 | 是，前提是副作用被隔离且只提交权威轨迹 |
| DSP | 2025 | 多步动作/规划序列 | Approximation 与 Target 规划并行 | 快 Approximation Agent + 慢 Target Agent | 在线预测动态深度 k；expectile/offset 控制成本 | 逐步对齐；首个失配后取消后续线程并回到 Target | 论文目标为无损，最终计划遵循 Target |
| PASTE | 2026 | 带具体参数的未来工具调用 | LLM 仍在生成当前 reasoning/action | 历史轨迹中的控制流模式与数据流映射 | 模式置信度、收益和资源联合准入 | 规范化工具名与参数匹配；结果隔离；失配丢弃 | 是，前提是工具满足只读、可隔离或策略批准 |
| DualSpec | 2026 | Search / Visit 动作 | 用轻量 Draft+Critic 避免完整大模型推理 | 小模型带推理 + 大模型无推理 | 按动作类型异构选择；阈值控制 intervention | 大模型语义 Critic；低分才回退完整推理 | 否；语义接受允许与权威动作不完全相同 |
| SPORK | 2026 | 同一模型未来将生成的工具调用 | Actor 仍在生成长 CoT | Target 模型自身的 Prefix-KV fork probe | 置信度决定最早提交时刻 | 工具名+参数严格匹配；失配串行执行；前缀 Token 回收 | 条件无损；严格匹配与安全工具成立时不改主轨迹 |
| Speculate with Memory | 2026 | 动作、观测、观测→动作链 | 环境或模型的空闲/等待时间 | 小 Speculator + 在线记忆 | 转移表、情景检索、混淆抑制 | Actor 轨迹不变；只提前运行可安全处理的分支 | 是，论文明确要求 Actor 轨迹与非投机一致 |
| Joint Agent–Speculator RL | 2026 | 下一工具调用 | 从部分 Agent 轨迹发起自投机 | 同一模型双模式，共享权重与 Prefix KV | SFT warmup + Agent/Speculator 交替 RL | 以 Agent 自身实际调用作为 Hit@1 标签 | 否（严格定义）；训练改变了 Agent 策略，实验上保持成功率 |
| SPAgent | 2025 | 搜索动作 | 早期跳过推理；后期与主推理并行 | 同一模型直接采样多个动作 | 激进/验证两阶段；自评分切换；负载感知调度 | 早期不验证；后期严格动作命中后复用 | 否；早期明确省略验证 |
| Speculative Interaction Agents | 2026 | 基于部分用户输入的工具调用 | 用户流式输入、异步工具返回 | 云端实时模型或经过 clock-based SFT 的 3B 模型 | 事件驱动；工具依赖图；支持修改/取消 | 后续输入可修正；敏感工具等待最终 commit | 否；报告轻微准确率下降 |
| Sherlock | 2025 | 已生成工作流中的下游节点 | 上游 Verifier 正在运行 | 不预测动作；沿依赖图向前执行 | 验证延迟与预算限制投机深度 | Verifier 修正后按依赖关系选择性回滚 | 否；以可靠性提升和阈值回滚为目标 |

## 3. 这 10 篇论文之间的结构关系

```text
基础范式
└── Speculative Actions：外部快 Speculator + 权威 Actor + 命中复用
    ├── 投机多远？
    │   └── DSP：在线预测动态深度 k，控制 latency-cost
    ├── 如何从真实系统中找到预测？
    │   └── PASTE：轨迹模式 + 数据流映射 + LLM/Tool 协同调度
    ├── 不同动作是否应使用同一种投机方法？
    │   └── DualSpec：Search/Visit 异构草稿 + 语义验证
    ├── 能否不使用外部 Speculator？
    │   ├── SPORK：同模型 KV fork，训练免费
    │   └── Joint Agent–Speculator RL：同模型双模式联合训练
    ├── Speculator 能否从历史中不断学习？
    │   └── Speculate with Memory：转移表 + 情景记忆 + 混淆抑制
    ├── 是否所有步骤都必须验证？
    │   └── SPAgent：早期激进、后期验证 + 负载调度
    ├── 投机窗口能否来自用户尚未说完？
    │   └── Speculative Interaction Agents：流式输入 + 异步 I/O
    └── 投机对象能否不是下一动作？
        └── Sherlock：验证期间向前执行下游工作流节点
```

## 4. 组会 Survey 的推荐精讲集合

建议制作独立 8 页以内 PPT 的 5 篇论文：

1. Speculative Actions：基础范式；已有 PPT，可直接作为总览起点。
2. Dynamic Speculative Agent Planning：动态多步深度与延迟—成本控制。
3. PASTE：从算法走向完整 Agent Serving 系统。
4. SPORK：训练免费的同模型自投机。
5. Speculate While You Reason：通过联合 RL 训练自投机 Agent。

其余 5 篇不单独做完整 PPT，而是在最终 Survey 总结页中按机制对比：

- DualSpec：动作异构性与语义验证。
- Speculate with Memory：有状态、跨任务学习。
- SPAgent：分阶段投机和系统调度。
- Speculative Interaction Agents：流式人机交互。
- Sherlock：验证窗口中的工作流投机。

选择理由不是“这些论文更可能产生创新点”，而是它们能组成一条完整、易讲清楚的技术演进线：

```text
外部 Speculator 基础范式
→ 动态决定投机深度
→ 从轨迹模式构造可执行工具调用并联合调度
→ 不训练的同模型自投机
→ 经过联合训练的同模型自投机
```
