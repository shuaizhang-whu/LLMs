### 主题 C：代理指标与真实目标反向——已有四个自认案例

| 论文 | 代理量 | 真实量 | 方向 |
|---|---|---|---|
| SU | per-call 错误率 21%→15% | resolved rate 49%→**44%** | **反向** |

> "For Hit@1 evaluation, a prediction is correct only if the parsed tool name and the complete parsed argument dictionary **exactly match**... For the shaped speculation reward used during RL, we ... compute **macro token-F1** over target argument keys ... This keeps the training reward dense enough to provide partial credit for close arguments, while **the deployment reuse metric remains exact structured-call equality**."

**训练给"参数接近"发部分分，部署时参数不对结果完全作废。** 而评估期根本不执行投机（`appendix.tex:6-13`："the environment executes only the agent's actual call"），所以 Hit@1（44.1→61.2）是在冻结轨迹上比出来的。

### 主题 E：我实测的深度衰减（HotpotQA，论文原始 API 运行，95 runs）

```
P(L≥1) = 0.874    r₁ = 0.874
P(L≥2) = 0.558    r₂ = 0.639
P(L≥3) = 0.274    r₃ = 0.491
P(L≥4) = 0.011    r₄ ≈ 0.04
```

对照：SA 的深度定理（`thm:depth`）假设"Let p be the probability that a speculation is correct **at each step**"——**常数 p**。实测 r_d 递减。

**这不是新发现**：AOSpec 已量化同一现象（`motivation.tex:94`，【已核实】）"collapse multiplicatively from **20.9% at one step to 2.4% at three and 1.2% at five**"，并据此**放弃链式多步路线**，改做「目标动作 + origin state」。

→ **结论：深度这条线在本领域已被判定不可用，不要再作为主贡献。**

## 第二部分：候选研究问题

### RQ1（主推，方法型）投机准入判据：从「匹配概率」改为「可复用且及时」

**场景与可观察的损失**

在线工具 serving。工具延迟跨步异质——SPORK 实测（`A_appendix.tex:133-136`）：**36% 的 turn 工具时间 < 0.72s（= probe 派发时间），零可重叠；47% 在 [0.72, 2]s，重叠 ≤1.28s；只有 17% 的 turn 能产生实质重叠。端到端 -18% 由这 17% 支撑。**

现有准入判据取 `P(match)`（置信度）。但真实收益取决于三个量：

1. P(match)——匹配概率
2. Δ——残余可隐藏窗口（AOSpec 叫 runway）
3. c_rej——拒绝成本（probe 计算 + 已派发工具的浪费）

**当 Δ 与 c_rej 跨步异质时，`P(match)` 的排序 ≠ 净节省的排序。**

**核心假设与机理**

> 在相同探测预算下，按「预测净节省」准入，端到端 wall-clock 低于按「匹配概率/置信度」准入。

机理：收益 ≈ `P(match) · min(Δ, T_tool) − c_rej`，而现有系统只优化了第一项。

**最近邻与尚未验证的差距**

- **PASTE**：声称"收益与资源感知选择"，但原文只有一句描述性文字（`4_system_design_atc_v1.tex:83`）——**无公式、无单位、无权重**；唯一的式子 `priority(i)=ExposedToolGain/LLMPressure+Aging`（`:138-144`）两个分量都没有估计器，`γ/P_low/P_high` **全文从未给值**。**这是你笔记第四部分 #3 让得过早的位置。**
- **Speculative Actions**：有成本-延迟定理，但用**固定延迟 a, b** 且假设分支独立；且它优化的是"调 k 这个旋钮"，不是"这一发该不该发"。
- **SPORK**：有 break-even 条件 `α·T_ov ≥ T_oh`（`A_appendix.tex:35`），但是**单步**的、只用接受率、且正文给的是简化版（差一个 `(1-α)` 因子）。
- **AOSpec**：有 runway 公式和 origin state，但 origin state 只覆盖文件系统，且**全部实验是固定轨迹回放**。

**公平基线（尤其是简单强基线）**

1. 置信度阈值（SPORK D2 原版，θ=0.90）
2. SA 的固定阈值规则（50%）
3. 随机准入 + 同预算
4. **温度重标定后的置信度**——防止把"校准改进"误当"新机制"

**能证伪假设的最小实验**

在 SA 的 HotpotQA 本地复现上，固定 probe 派发预算，比较两种准入策略的**在线**端到端 wall-clock。**若两者差异不显著（<3%）→ 假设死。**

**指标**

端到端 wall-clock（**在线，不是回放时间重建**）、EM/F1、probe 派发次数、被浪费的派发数、拒绝成本、命中但未及时到达的比例。

**可复用 / 需新增**

- 复用：SA 本地复现——`install_prefetched_search` / `discard_prefetched_searches` / `prefetch_metadata` 已经是完整的"投机→接受/丢弃"生命周期 + 记录点；每条轨迹里已有 `time_taken`
- 新增：残余等待窗口的在线估计 + 净节省判据 + **在线实验协议**（这是本方案最大的工程量）

**难度与资源**：中等。单卡 3090 + Qwen2.5-7B 够。**停止条件**：置信度准入与净节省准入的端到端差异 <3%，或无法复现。

### RQ2（方法型）投机资格的自动判定——白名单之外

**场景与损失**：所有系统都用**人工白名单**排除写工具（主题 A）。SPORK 承认写工具全部串行，但**这类工具在真实负载中的占比、以及被放弃的收益，无人量化**。

**核心假设**：工具的可投机性可以由**调用点可观测的信号**自动判定（调用签名、参数模式、该调用历史的副作用统计、目标系统的可回滚性），且其收益/风险曲线优于人工白名单。

**最近邻**：AOSpec 的 CoW 隔离是唯一机制，但只覆盖文件系统，且依赖"concurrent work under anonymous review"的沙箱运行时（`methodology.tex:193`，未公开）。

**最小（且是 kill）实验**：在 SA 仓库里已有的 e-commerce（τ-bench retail）上统计——**写操作占总工具调用的比例**。
- 若 <5% → **这个方向直接停**，因为放弃了也没损失多少
- 若 >20% → 值得做

**难度**：中高，依赖 τ-bench 环境可跑通与是否需 API。

### RQ3（测量型）在线 vs 回放：结论在什么条件下反转

**场景**：三种主流方法用固定轨迹回放评估——AOSpec 全部实验（`experiments.tex:65-67`）、Speculate with Memory 主实验（`main.tex:398`）、SWYR 评估（`appendix.tex:6-13`）。而回放**切断了"投机改变后续轨迹"这条反馈路径**，且 AOSpec **全程没有报告任何任务成功率**。

**核心假设**：回放与在线下的方法排序不同，且差异集中在特定条件下（工具延迟分布、并行度、状态变更频率）。

**最小实验**：同一方法在回放与在线两种协议下跑同一批任务，比较排序是否一致；用你已有的 `online_top3` 与回放目录对比即可起步。

**定位**：这条**更是 RQ1 的前置基础设施**——RQ1 要求在线测量，而在线协议本身没有被验证过。

## 第四部分：我的建议

**优先做 RQ1，并把 RQ3 当作它的第一步。**

理由：

1. **有已核实的空位**：PASTE 的"收益感知"是无公式的口号，SA 的定理用常数延迟且假设独立，SMC 承认宏数是错目标但给不出正确目标，AOSpec 的 runway 依赖未公开运行时。四家都停在"知道不该只看命中率"，没有一家给出可测量、可校准的判据。
2. **不需要训练、不需要 API 预算**，单卡 3090 可跑，直接建立在你已经复现的 SA 上。
3. **可证伪且停止条件明确**：固定预算下两种准入策略的端到端差异 <3% 就死。
4. **机理层面而非模块组合**：它主张的是"决策变量选错了"，不是"加一个组件"。

**风险（必须提前说清）**：审稿人会说"这不就是 cost-aware scheduling 吗"。因此**必须**在第 2 条里把那四个基线跑满，尤其是**温度重标定基线**——如果净节省准入的优势能被"校准得更好的置信度"解释掉，贡献就不成立。
