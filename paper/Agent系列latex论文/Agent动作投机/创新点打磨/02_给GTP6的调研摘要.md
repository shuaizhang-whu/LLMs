## 二、已核实的硬事实

### 1. 成本记账普遍不完整

- **MASW**：speedup 明确排除 prefill（`appendix.tex:63-69`），而 prefill 是它唯一新增的开销（32K 下带记忆的 draft prefill 是原始的 4.35×）
- **SMC**：基线 1 GPU、方法 3 GPU。摘要 18.59% 是对 1-GPU 基线；**等硬件口径只有 10.23%**。分开陈述这两者的段落被注释掉
- **AOSpec**：drafter 独占 2 张 H200，延迟报告里无 GPU 成本项
- **SPORK**：自己测到 "dispatching the fork simultaneously with the main request causes **2.5× prefill contention**"

### 2. 代理指标与真实目标反向 —— 已有四个自认案例

- **SU**：per-call 错误率 21%→15%，而 resolved rate **49%→44%**
- **SMC**：提交次数与跳过步数都更多的版本**反而慢 1.64%**，作者自评 "Raw macro count is thus the wrong objective"
- **Speculate with Memory**：全配置 memory **比简单配置更差**
- **AgentSpec**：结构隔离贡献仅 1.27× vs 1.30×

### 3. 最直接的一条：训练奖励与部署条件被写成两个东西

Speculate While You Reason，`sections/appendix.tex:74-81`：

> 训练时对"工具名匹配 + 参数接近"发 macro token-F1 部分分；而部署复用要求名字与**全部参数完全一致**。

即：**梯度方向系统性偏向部署中不可用的输出。**

### 4. 「投机准入」的最近邻都没有可用的成本模型

- **PASTE** 声称"收益与资源感知选择"，但原文只有一句描述性文字，**无公式、无单位、无权重**；γ / P_low / P_high 全文从未给值
- **Speculative Actions** 的成本-延迟定理用**固定延迟 a, b** 且假设分支独立
- **SPORK** 有 break-even 条件 `α·T_ov ≥ T_oh`，但是**单步**的、只用接受率
- **AOSpec** 有 runway 和 origin state，但 origin state **只覆盖文件系统**，且全部实验是**固定轨迹回放**

### 5. SPORK 实测的工具延迟分布（关键）

36% 的 turn 工具时间 < 0.72s（= probe 派发时间），**零可重叠**；47% 重叠 ≤1.28s；只有 **17%** 的 turn 能产生实质重叠。端到端 -18% 全靠这 17%。

### 6. SPORK 对副作用零讨论

它是把工具派发得最早的（fork 在主请求第一个 token 之后）。穷举全文，关于副作用只有三句"我们只做只读工具"的声明；GAIA 上 2124 次 probe 派发 / 165 query，只计时间不计资源。

## 三、目前的候选方向（请批判性评估，不要附和）

**RQ1：把投机准入判据从「匹配概率」改成「可复用且及时」**
- 假设：相同探测预算下，按预测**净节省**准入，在线端到端 wall-clock 低于按匹配概率准入
- 机理：收益 ≈ `P(match)·min(Δ, T_tool) − c_rej`，现有系统只优化了第一项
- 证伪实验：固定 probe 预算，比较两种准入策略的**在线**端到端延迟。差异 <3% 则假设死

**RQ2：投机资格的自动判定**（白名单之外）。kill 实验：统计真实负载里写操作占比，<5% 直接停。

**RQ3：在线 vs 回放的一致性**。AOSpec 全部实验、Speculate with Memory 主实验、SWYR 评估都用固定轨迹回放，切断了"投机改变后续轨迹"的反馈。
