# From AR to Diffusion: Efficiently Adapting Large Language Models with Strictly Causal and Elastic Horizons 论文总结

## 1. 论文基本信息

- **论文题目**：From AR to Diffusion: Efficiently Adapting Large Language Models with Strictly Causal and Elastic Horizons
- **方法名称**：FLUID，Flexible Unidirectional Inference Diffusion
- **核心任务**：将已有自回归大语言模型高效适配为扩散式并行生成模型
- **主要关注点**：文本生成效率、AR checkpoint 复用、因果结构对齐、动态生成窗口
- **直接相关方向**：自回归语言模型、离散扩散语言模型、Block Diffusion、Semi-Autoregressive Generation

---

## 2. 研究背景

当前主流大语言模型大多采用自回归生成方式。它的生成逻辑是从左到右逐个预测 token：已经生成的 token 作为历史上下文，模型再预测下一个 token。这种方式稳定，适合复杂推理、代码生成和长链条文本生成，但缺点也明显：生成速度受限于串行依赖，每一步都必须等上一步完成。

扩散语言模型提供了另一条路线。它可以先把文本中的若干位置变成 `[MASK]`，再通过去噪过程恢复这些 token。由于多个 mask token 可以同时预测，扩散模型具备并行生成潜力。不过标准扩散语言模型通常使用双向注意力。它在恢复当前位置时，可以同时看左边和右边的上下文，更像是在做填空任务。

这里出现了一个关键矛盾：GPT、LLaMA 这类大模型在预训练时采用严格因果注意力，只能看历史 token，不能看未来 token。标准扩散模型使用双向注意力，会破坏这种因果结构。因此，已有 AR checkpoint 很难直接迁移到标准 diffusion 生成框架中。如果重新从头训练 diffusion LLM，成本又非常高。

Block Diffusion 试图折中：块与块之间按自回归顺序生成，块内部用 diffusion 并行恢复。它比纯 AR 更快，也比完全双向 diffusion 更接近 AR 模型。但它仍有两个问题。一个是 block size 固定，简单文本和复杂文本都用同样的生成窗口；另一个是 block 内部通常仍是双向注意力，和 AR checkpoint 的因果结构仍不完全一致。

FLUID 就是在这个背景下提出的。它的目标是：保留 AR 模型的因果先验，同时引入 diffusion-style 的并行生成能力，并且根据当前上下文难度动态决定一次生成多少 token。

---

## 3. 论文核心问题

论文要解决的问题可以分成三层：

1. **AR 模型生成稳定但串行慢**

   AR 模型每次只能生成一个 token。长文本生成、复杂推理和代码生成时，延迟较高。

2. **标准 Diffusion 模型并行但和 AR checkpoint 不匹配**

   标准 diffusion denoiser 常用双向注意力，当前位置可以看未来 token。这和 AR 模型预训练时的 causal mask 不一致，导致已有 AR 权重难以直接复用。

3. **Block Diffusion 是折中方案，但固定 block 和块内双向注意力仍有缺陷**

   固定 block size 无法适应自然语言的信息熵变化。简单位置可以大步生成，复杂位置需要小步生成。固定窗口容易在高熵区域产生语义断裂或错误累积。

---

## 4. 方法总览：FLUID 的整体思想

FLUID 的方法可以概括为：

> 在 Block Diffusion 的基础上，将固定块改成动态窗口，将块内双向注意力改成严格因果注意力，再通过 K-Head 和置信度门控控制实际生成步长。

它包含三个关键模块：

1. **Strictly Causal Diffusion Backbone**

   在扩散去噪过程中仍使用因果注意力。当前位置只能看历史，不能看未来。这样 diffusion-style generation 可以和 AR checkpoint 的预训练结构对齐。

2. **Elastic Horizon Modeling**

   使用一个轻量 K-Head，根据当前 hidden state 预测当前适合生成的窗口长度 \(K_t\)。简单区域大步生成，复杂区域小步生成。

3. **Dynamic Causal Inference**

   推理时先预测一个 mask block，再并行去噪，然后通过 confidence gating 只接受连续高置信度 token。这样计划窗口和实际提交窗口可以不同。

---

## 5. 基础公式与方法原理

### 5.1 自回归语言模型公式

论文中的自回归建模公式为：

\[
p_{\mathrm{AR}}(x)=\prod_{i=1}^{L}p_{\theta}(x_i \mid x_{<i})
\]

其中：

- \(x=[x_1,x_2,\dots,x_L]\) 表示完整 token 序列；
- \(L\) 是序列长度；
- \(x_i\) 是第 \(i\) 个 token；
- \(x_{<i}\) 表示第 \(i\) 个 token 前面的所有历史 token；
- \(p_{\theta}(x_i \mid x_{<i})\) 表示模型在看到历史 token 后预测当前 token 的概率；
- \(\theta\) 是模型参数。

这个公式的作用是说明 AR 模型的基本生成机制：整句话的概率被拆成一系列从左到右的条件概率乘积。它的优点是严格保持因果顺序，生成逻辑稳定。缺点是每一步都依赖前一步结果，无法天然并行。

FLUID 要保留的就是这个公式背后的因果结构。即使引入 diffusion，它也不希望模型像普通填空模型那样看未来 token。

---

### 5.2 离散扩散语言模型的加噪公式

扩散语言模型的前向加噪过程写作：

\[
q(x_{t,i}\mid x_{0,i})
=
\alpha_t \mathbb{I}(x_{t,i}=x_{0,i})
+
(1-\alpha_t)\mathbb{I}(x_{t,i}=[M])
\]

其中：

- \(x_0\) 表示原始干净文本；
- \(x_t\) 表示在时间步 \(t\) 被加噪后的文本；
- \(x_{0,i}\) 表示原始文本第 \(i\) 个 token；
- \(x_{t,i}\) 表示时间步 \(t\) 下第 \(i\) 个位置的 token；
- \([M]\) 是 mask token；
- \(\alpha_t\) 表示保留原 token 的概率；
- \(1-\alpha_t\) 表示把 token 替换成 `[M]` 的概率；
- \(\mathbb{I}(\cdot)\) 是指示函数，条件成立为 1，否则为 0。

这个公式的作用是定义文本扩散模型如何破坏文本。它没有像图像扩散那样加入高斯噪声，而是把 token 随机替换成 `[M]`。模型后续要学习从带 mask 的文本中恢复原始 token。

---

### 5.3 扩散模型的去噪训练目标

扩散语言模型的训练目标为：

\[
\mathcal{L}(\theta)
=
-\mathbb{E}_{t,x_0,x_t}
\left[
w(t)
\sum_{i=1}^{L}
\mathbb{I}[x_{t,i}=[M]]
\log p_{\theta}(x_{0,i}\mid x_t)
\right]
\]

其中：

- \(\mathbb{E}_{t,x_0,x_t}\) 表示对扩散时间、原始文本和加噪文本取期望；
- \(w(t)\) 是与时间步 \(t\) 有关的权重；
- \(\mathbb{I}[x_{t,i}=[M]]\) 用来筛选被 mask 的位置；
- \(p_{\theta}(x_{0,i}\mid x_t)\) 表示模型根据带噪文本 \(x_t\) 预测原始 token \(x_{0,i}\) 的概率。

这个公式的核心作用是训练模型恢复被 mask 的 token。只有被 mask 的位置会计算损失，没有被遮住的位置不参与损失。普通 diffusion denoiser 通常可以看到完整 noisy context，因此它往往是双向的。FLUID 后续的关键改动，就是把这个恢复过程放到严格因果注意力下。

---

### 5.4 Block Diffusion 的概率分解

Block Diffusion 将序列划分成多个块：

\[
p_{\theta}(x)=\prod_{b=1}^{B}p_{\theta}(x^b\mid x^{<b})
\]

其中：

- \(x^b\) 表示第 \(b\) 个 block；
- \(B\) 表示 block 总数；
- \(x^{<b}\) 表示第 \(b\) 个 block 之前的所有 block；
- \(p_{\theta}(x^b\mid x^{<b})\) 表示在历史 block 条件下生成当前 block 的概率。

这个公式说明 Block Diffusion 是一种块级别自回归。它不是每次生成一个 token，而是每次生成一块 token。块与块之间保持从左到右顺序，块内部可以并行恢复。

FLUID 的方法本体和这个公式关系很强。它继承了 block-wise 生成思想，但改掉了两个关键点：固定块长度和块内双向注意力。

---

## 6. FLUID 的关键模块

### 6.1 Strictly Causal Alignment：严格因果对齐

FLUID 在 Transformer 注意力中使用下三角 causal mask：

\[
\mathrm{Attention}(i,j)=
\begin{cases}
\frac{q_i k_j^\top}{\sqrt{d_k}}, & \text{if } j \le i,\\
-\infty, & \text{otherwise}.
\end{cases}
\]

其中：

- \(i\) 是当前 query 位置；
- \(j\) 是被关注的 key 位置；
- \(q_i\) 是第 \(i\) 个位置的 query 向量；
- \(k_j\) 是第 \(j\) 个位置的 key 向量；
- \(d_k\) 是 key 向量维度；
- \(j \le i\) 表示只能看当前位置及其之前的位置；
- \(j>i\) 时 attention score 被设为 \(-\infty\)，经过 softmax 后注意力权重为 0。

这个公式的作用非常关键。它把 diffusion denoising 从双向填空改成单向因果生成。模型恢复当前 token 时不能看未来 token，只能利用历史 token。这样做的目的，是让 diffusion 过程和 AR checkpoint 的预训练归纳偏置一致。

从方法角度看，这也是 FLUID 中最核心的改动。消融实验显示，加入 causal mask 带来的提升最大，说明结构对齐是性能提升的主要来源。

---

### 6.2 Elastic Horizon：动态生成窗口

FLUID 使用 K-Head 预测当前适合生成的 horizon。公式为：

\[
z_t = \mathrm{MLP}(h_t)
\]

\[
P_{\phi}(k \mid h_t)=\mathrm{Softmax}(z_t)_k
\]

其中：

- \(h_t\) 表示当前决策点 \(t\) 的 hidden state；
- \(\mathrm{MLP}\) 是轻量的 K-Head；
- \(z_t\) 是对不同候选 horizon 的打分；
- \(k \in \{1,\dots,K_{\max}\}\) 表示候选生成窗口长度；
- \(P_{\phi}(k \mid h_t)\) 表示当前上下文下选择 horizon \(k\) 的概率；
- \(\phi\) 是 K-Head 的参数。

这个模块的作用是让模型学会判断“当前一次生成几个 token 合适”。普通 Block Diffusion 使用固定 block size，例如每次生成 8 个或 16 个 token。FLUID 则让 K-Head 根据当前上下文动态选择 \(K_t\)。

低熵、模板化、确定性强的位置可以选择大 \(K_t\)。高熵、复杂推理、代码逻辑或语义转折位置可以选择小 \(K_t\)。这就是 Elastic Horizon 的核心意义。

---

### 6.3 Competence Boundary Supervision：能力边界监督

训练 K-Head 的难点是没有现成标签。数据里不会告诉模型“当前位置应该生成几个 token”。论文通过未来 token 的预测损失构造一个 oracle horizon：

\[
K_t^*
=
\max
\left\{
k
\mid
\frac{1}{k}
\sum_{j=1}^{k}
L_{t+j}
< \tau
\right\}
\]

其中：

- \(K_t^*\) 是当前决策点的能力边界；
- \(L_{t+j}\) 表示未来第 \(t+j\) 个位置的预测损失；
- \(k\) 表示候选窗口长度；
- \(\tau\) 是损失阈值；
- \(\frac{1}{k}\sum_{j=1}^{k}L_{t+j}\) 表示未来前 \(k\) 个 token 的平均预测损失。

这个公式的含义是：从当前位置向后看，如果未来前 \(k\) 个 token 的平均 loss 低于阈值 \(\tau\)，说明模型对这段内容比较有把握。取满足条件的最大 \(k\)，作为当前模型能够可靠生成的最大范围。

这个 \(K_t^*\) 不是人工标注，而是由模型自己的预测能力估计出来的。它相当于回答一个问题：当前模型最多能安全向前生成多远。

为了避免标签过于僵硬，论文没有直接使用 one-hot 标签，而是构造高斯软标签：

\[
Q(k)
\propto
\exp
\left(
-\frac{(k-K_t^*)^2}{2\sigma^2}
\right)
\]

其中：

- \(Q(k)\) 是以 \(K_t^*\) 为中心的软标签分布；
- \(\sigma\) 控制分布宽度；
- \(k\) 离 \(K_t^*\) 越近，权重越高；
- \(k\) 离 \(K_t^*\) 越远，权重越低。

这个公式的作用是体现 horizon 的有序性。比如最优窗口是 8，那么预测 7 或 9 比预测 1 更接近正确答案。软标签比 one-hot 更适合训练 K-Head。

## 7. 训练流程

FLUID 采用两阶段训练。

### 7.1 Stage I：Joint Causal Backbone Training

第一阶段训练 backbone，冻结 K-Head。目标是让原来的 AR 模型学会在严格因果约束下做 diffusion-style denoising。

训练时随机采样一个 horizon：

\[
K \sim U[1,K_{\max}]
\]

然后把序列划分成历史部分 \(x_{\mathrm{obs}}\) 和 mask 目标部分 \(x_{\mathrm{mask}}\)。模型需要在只能看历史的情况下恢复 mask span。

这一阶段的损失为：

\[
\mathcal{L}_{\mathrm{Stage1}}
=
-\sum_{x_i\in x_{\mathrm{obs}}}
\log p_\theta(x_i\mid x_{<i})
+
\mathbb{E}_t
\left[
-\sum_{x_j\in x_{\mathrm{mask}}}
w_t\log p_\theta(x_j\mid x_t)
\right]
\]

它由两部分组成。

AR loss：

\[
-\sum_{x_i\in x_{\mathrm{obs}}}
\log p_\theta(x_i\mid x_{<i})
\]

这一项用于维持模型原有的自回归语言能力。它防止模型在适配 diffusion 过程中丢失原来的语言建模能力。

Diffusion denoising loss：

\[
\mathbb{E}_t
\left[
-\sum_{x_j\in x_{\mathrm{mask}}}
w_t\log p_\theta(x_j\mid x_t)
\right]
\]

这一项用于训练模型恢复 mask span。区别在于，这里的恢复过程受到 causal attention 约束，不允许看未来 token。

论文还使用了 Stochastic Restoration，在 mask span 中注入一定比例噪声，提高模型对不完美输入的鲁棒性。

这一阶段的本质是：先让 backbone 学会“在不偷看未来的情况下，一次恢复一段 mask token”。

---

### 7.2 Stage II：Probabilistic Horizon Training

第二阶段冻结 backbone，只训练 K-Head。目标是让 K-Head 学会根据当前 hidden state 预测合适的 horizon 分布。

损失函数为：

\[
\mathcal{L}_{\mathrm{Stage2}}
=
D_{\mathrm{KL}}
\left(
Q
\|
P_\phi(\cdot\mid h_t)
\right)
\]

其中：

- \(Q\) 是根据 \(K_t^*\) 构造的高斯软标签；
- \(P_\phi(\cdot\mid h_t)\) 是 K-Head 预测的 horizon 分布；
- \(D_{\mathrm{KL}}\) 是 KL 散度，用来度量两个分布之间的差异。

这个公式的作用是让 K-Head 的预测分布接近能力边界监督得到的软标签。训练完成后，K-Head 就能在推理时根据上下文判断当前该走大步还是小步。

---

## 8. 推理流程：Dynamic Causal Inference

训练完成后，FLUID 使用动态因果扩散推理。核心思想是：

> 先规划一个候选生成窗口，再并行预测窗口内 token，最后只提交连续高置信度 token。

推理流程如下：

1. 输入当前上下文 \(x\)。
2. 编码当前上下文，得到 hidden state \(h\)。
3. K-Head 预测当前 horizon：

   \[
   K = \arg\max f_\phi(h)
   \]

4. 在上下文后拼接 \(K\) 个 mask token：

   \[
   Y=[M]^K
   \]

5. 模型对 \([x;Y]\) 做一次 parallel denoising sweep，得到每个 mask 位置的预测分布。
6. 当前第一个位置的 token 强制接受，保证每轮至少生成一个 token。
7. 后续 token 通过置信度门控判断：

   \[
   \max(P[j])>\gamma
   \]

   如果最大概率超过阈值 \(\gamma\)，接受该 token；如果某个位置置信度不足，则停止接受后续 token。

8. 将连续通过置信度检查的 token 拼接到上下文中，进入下一轮生成。

这里有两个窗口概念：

- \(K\)：计划窗口，由 K-Head 预测；
- \(1+\Delta\)：实际提交窗口，由 confidence gating 决定。

这比固定 Block Diffusion 更灵活。模型可以在简单片段快速前进，也可以在复杂区域自动退回到接近 AR 的小步生成。

---

## 9. 和 Block Diffusion 的关系

拆开论文包装看，FLUID 的直接方法基线确实是 Block Diffusion / Semi-Autoregressive Diffusion。

传统 Block Diffusion 的形式是：

- 块与块之间自回归；
- 块内部扩散去噪；
- block size 通常固定；
- block 内部通常允许双向注意力。

FLUID 的改法是：

- 块与块之间仍保持从左到右；
- 块内部也改成严格因果注意力；
- 固定 block size 改成动态 horizon；
- 推理阶段通过置信度门控决定实际提交长度。

所以 FLUID 不是完全从零提出新的生成理论，而是对 Block Diffusion 范式做结构性改造。它保留了 block-wise 并行生成的思想，但让这个框架更适合复用 AR checkpoint。

更直接地说：

> Block Diffusion 是固定块、块内双向；FLUID 是动态块、块内因果。

这个判断对理解论文创新点很重要。论文表述上强调“From AR to Diffusion”，但方法本体更接近“把 Block Diffusion 改得更像 AR，更适合 AR 权重迁移”。

## 10. 实验结论简述

论文使用 openPangu-Embedded-7B 作为初始化模型。训练分为两个阶段：

- Stage I：backbone fine-tune 约 32,000 iterations；
- Stage II：K-Head 训练约 2,000 steps；
- 输入长度 1024；
- \(K_{\max}=16\)；
- 使用 Rank-16 LoRA 适配 backbone；
- 校准阈值 \(\tau=2.8\)。

评估任务包括：

- 通用能力：MMLU、IFEVAL；
- 数学推理：GSM8K、MATH500；
- 代码生成：HumanEval、MBPP。

主要结果中，FLUID-7B 在多个任务上接近或超过若干 diffusion baseline。报告结果包括：

- MMLU：67.8
- IFEVAL：57.7
- GSM8K：91.9
- MATH500：61.8
- HumanEval：60.4
- MBPP：53.6

消融实验显示：

- 不加 causal、不加 elastic 的 baseline 表现较弱；
- 只加 Elastic 提升有限；
- 只加 Causal 提升明显；
- Causal + Elastic 的完整 FLUID 最好。

这说明 Strictly Causal Alignment 是主要性能来源，Elastic Horizon 是进一步增强项，尤其对代码、结构敏感任务和复杂推理更有帮助。

推理效率方面，论文报告 FLUID 相比标准 diffusion baseline 有明显加速，并且在某些设置下比固定 \(K=16\) 的 block 方法更快。原因是固定大窗口在高熵位置容易产生等待和纠错成本，而 FLUID 可以动态缩短窗口。

## 11. 创新点分析

### 11.1 解决的问题是否明确

论文要解决的问题比较明确：已有 AR 大模型效果强，但生成串行；标准 diffusion 有并行潜力，但和 AR checkpoint 的双向/因果结构不匹配；Block Diffusion 虽然折中，但固定 block 和块内双向注意力仍有限制。

这个问题定义是扎实的。尤其是 AR checkpoint 复用和 diffusion 结构错配，是当前 AR-to-Diffusion 适配中的关键问题。

---

### 11.2 基于哪些已有方法或 baseline

从方法来源看，FLUID 主要基于以下路线：

1. **Autoregressive LLM**

   论文希望复用已有 AR backbone，例如 openPangu-Embedded-7B。

2. **Discrete Diffusion Language Model**

   FLUID 借用了 mask denoising 和 parallel generation 的思想。

3. **Block Diffusion / Semi-Autoregressive Diffusion**

   这是最直接的方法骨架。FLUID 保留“一次处理一段 token”的设计，但修改了 block 内部注意力和 block size。

4. **Dynamic decoding / confidence-based accepting**

   推理中的 confidence gating 和 speculative-like 接受机制有一定相似性，都是先预测多个候选，再提交可靠部分。

实验基线包括 AR baselines、Diffusion baselines，以及消融中的 bidirectional fixed-block baseline。

---

### 11.3 具体改进在哪里

FLUID 的主要改进可以概括为三点。

#### 改进一：块内双向注意力改成严格因果注意力

这解决了 diffusion denoising 和 AR checkpoint 不匹配的问题。它让扩散式生成仍遵守 AR 模型的历史依赖规则。

这是最重要的改进。消融实验中 causal mask 带来的提升最大，说明论文的核心性能收益主要来自结构对齐。

#### 改进二：固定 block 改成 Elastic Horizon

传统 Block Diffusion 的窗口大小固定。FLUID 使用 K-Head 动态预测当前 horizon，解决自然语言不同位置难度不同的问题。

这个改进让模型可以在低熵区域提高并行度，在高熵区域降低风险。它对代码和复杂推理任务更有价值。

#### 改进三：推理时加入 confidence gating

K-Head 预测的是计划窗口，但模型不会盲目接受全部 token。后续 token 必须超过置信度阈值才会被提交。这让 FLUID 不会因为一次预测太长而造成连续错误。

这个机制相当于给动态 horizon 增加了安全检查。

---

### 11.4 创新是否扎实

从“基础理论创新”角度看，FLUID 不是全新范式。它没有从零提出新的扩散目标，也没有完全重构语言模型生成理论。它的技术骨架仍然来自 Block Diffusion。

从“方法改造有效性”角度看，它的创新比较扎实。原因是两个主要改动都对应明确痛点：

- 双向注意力和 AR checkpoint 不匹配；
- 固定 block 无法适应文本信息熵变化。

论文的消融也能支撑这两个模块的作用。尤其是 causal mask 的贡献非常明显，说明这不是简单堆模块，而是抓住了 AR-to-Diffusion 适配中的关键矛盾。

因此，对这篇论文的合理评价是：

> FLUID 不是基础理论级创新，而是对 Block Diffusion 的结构性改进。它把 Block Diffusion 改得更因果、更动态、更适合复用 AR 大模型，方法完整度较高，创新点集中但有效。

---

## 12. 方法优点

1. **适合复用已有 AR checkpoint**

   通过严格因果注意力，FLUID 避免了标准 diffusion 的双向结构错配，更容易从已有 AR 模型迁移。

2. **兼顾速度和稳定性**

   简单位置可以并行生成多个 token，复杂位置可以缩短窗口，减少错误传播。

3. **训练流程相对清晰**

   两阶段训练逻辑明确：先训练 backbone 的 causal denoising 能力，再训练 K-Head 的 horizon 预测能力。

4. **模块间配合完整**

   Causal attention、K-Head、competence boundary supervision、confidence gating 之间形成闭环，不是孤立模块堆叠。

5. **消融实验能支撑核心设计**

   Causal 和 Elastic 两个变量拆得比较清楚，可以看出主要贡献来源。

---

## 13. 方法局限

1. **本质上仍依赖 Block Diffusion 框架**

   FLUID 的主要创新是改造 Block Diffusion，而不是提出完全独立的新生成理论。

2. **K-Head 训练依赖经验阈值**

   \(K_t^*\) 的构造依赖损失阈值 \(\tau\)。不同模型、不同任务、不同数据分布下，最优阈值可能变化。

3. **速度对工程实现敏感**

   论文中的速度比较没有完全覆盖 KV cache、FlashAttention 等真实推理优化条件。FLUID 的实际部署优势还需要更多系统层验证。

4. **验证 backbone 较有限**

   主要实验集中在一个 7B 级 backbone 上。方法是否稳定适用于更多模型族、更多尺寸、更多语言场景，还需要进一步实验。

5. **动态 horizon 可能带来额外控制成本**

   K-Head 预测、confidence gating、重复判断都会引入额外逻辑。对于短文本或强优化 AR 解码场景，收益未必稳定。

6. **能力边界监督仍是间接标签**

   \(K_t^*\) 来自未来 loss 探测，不是真实的人类或任务级最优 horizon。它更像模型内部能力估计，可能无法完全对应最终生成质量。

---

## 14. 对后续研究的启发

FLUID 给出的一个重要启发是：从 AR 到 diffusion 的迁移，关键不只是训练目标变化，更重要的是结构对齐。标准 diffusion 的双向注意力虽然自然适合填空式恢复，但它会破坏 AR checkpoint 的因果先验。对于已有大模型适配而言，因果结构可能比单纯并行能力更重要。

另一个启发是，文本生成的并行度应该是动态的。不同位置的信息熵不同，固定 block size 很难同时兼顾速度和准确性。未来的生成模型可能不再使用固定 token 步长，而是根据上下文难度、模型置信度、任务类型动态调节生成粒度。

这篇论文也说明，推理阶段的“接受策略”很重要。即使模型一次预测多个 token，也不应该全部提交。置信度门控、验证器、回退机制可能会成为并行生成方法中的关键组件。

---

## 15. 未来进一步改进方案

### 15.1 更可靠的 Horizon 标签构造

当前 \(K_t^*\) 主要由未来平均 loss 和阈值 \(\tau\) 决定。可以进一步探索更丰富的标签来源，例如：

- token-level entropy；
- margin confidence；
- 语义边界检测；
- 句法边界；
- 推理步骤边界；
- 代码语法结构边界；
- verifier 给出的质量反馈。

这样 K-Head 预测的 horizon 不只依赖 loss，而是结合语义、结构和任务难度。

---

### 15.2 将 K-Head 从分类器改成策略模型

当前 K-Head 是一个 horizon 分类器。未来可以把它改成轻量策略模型，根据生成收益动态决策。例如用强化学习或 bandit 方法，让模型直接优化“速度—质量”权衡。

奖励可以包含：

- 生成正确性；
- token 接受长度；
- 推理延迟；
- 重生成次数；
- 置信度稳定性；
- 下游任务得分。

这样 K-Head 不只是模仿能力边界，而是学习真正对最终生成有利的步长策略。

---

### 15.3 引入验证器式接受机制

当前 confidence gating 主要看 token 最大概率是否超过阈值 \(\gamma\)。这个判断比较局部。未来可以引入 verifier 或 lightweight critic，对候选 token span 做整体判断。

例如：

- 判断整段候选是否语义连贯；
- 判断代码候选是否符合语法；
- 判断数学推理步骤是否合理；
- 判断是否出现重复或退化生成。

这会比单 token confidence 更稳。

---

### 15.4 多尺度 Elastic Horizon

当前 K-Head 预测单一窗口长度 \(K_t\)。未来可以考虑多尺度窗口：

- token-level 小窗口；
- phrase-level 中窗口；
- sentence-level 大窗口。

模型可以根据上下文选择不同粒度的生成方式。简单模板句可以句块级生成，复杂推理可以 token-level 生成。

---

### 15.5 和 Speculative Decoding 结合

FLUID 的推理逻辑和 speculative decoding 有相似之处，都是先产生多个候选，再接受可靠部分。未来可以将 FLUID 的 causal diffusion block 作为 draft generator，再用 AR verifier 验证接受。

这样可能形成一种混合框架：

- diffusion 模型负责快速提出多个候选 token；
- AR 模型负责严格验证；
- K-Head 控制候选跨度；
- confidence gating 控制提交长度。

这条路线可能进一步提升实用推理速度。

---

### 15.6 更公平的系统级速度评估

未来工作需要在更真实的推理设置下评估 FLUID，例如：

- 开启 KV cache；
- 使用 FlashAttention；
- 不同 batch size；
- 长上下文；
- 多轮对话；
- GPU 与 CPU 混合环境；
- serving 场景中的吞吐和延迟。

只有在这些设置下仍然有稳定加速，FLUID 的工程价值才更有说服力。

---

### 15.7 扩展到更多 backbone 和任务

论文主要展示了 7B 级模型结果。未来可以测试：

- LLaMA 系列；
- Qwen 系列；
- Mistral 系列；
- DeepSeek 系列；
- 更大尺寸模型；
- 多语言任务；
- 长文本生成；
- 工具调用和代码执行任务。

这能判断 Strictly Causal Diffusion 是否是通用适配策略。

---

## 16. 可探索的新创新点

基于 FLUID 的思路，可以进一步探索以下研究方向：

### 16.1 Entropy-aware AR-to-Diffusion Adaptation

把信息熵估计作为核心模块，不只预测 horizon，也用于调整 denoising steps、temperature、置信度阈值和接受策略。这样可以形成更完整的动态生成控制框架。

### 16.2 Structure-aware Elastic Horizon

不同任务有不同结构。代码有语法块，数学有推理步骤，普通文本有短语和句子边界。未来可以让 horizon 预测器感知任务结构，而不是只基于 hidden state 预测长度。

### 16.3 Causal Diffusion with Step-level Verification

在每个动态 block 生成后加入步骤级验证器。数学任务验证推理步骤，代码任务验证语法或单元测试，问答任务验证事实一致性。这可以减少并行生成带来的错误累积。

### 16.4 Adaptive Block Diffusion for Long-context Generation

长文本生成中，不同段落的信息密度差异很大。可以将 FLUID 扩展到长上下文生成，让模型在叙述性文本中大步走，在关键推理或事实密集位置小步走。

### 16.5 Joint Training of Backbone and Horizon Policy

当前训练分成 backbone 和 K-Head 两阶段。未来可以探索联合训练，让 horizon policy 和 denoising backbone 相互适应。难点是训练稳定性，但潜在收益更大。

---

## 17. 总体评价

FLUID 的核心价值在于，它抓住了 AR-to-Diffusion 适配中的两个真实问题：标准 diffusion 的双向注意力和 AR checkpoint 不匹配，固定 Block Diffusion 无法适应文本难度变化。它通过严格因果注意力和动态 horizon，把 Block Diffusion 改造成更适合 AR 大模型迁移的形式。

从创新性质看，它不是从零提出新生成范式，而是对 Block Diffusion 的结构性改造。这个改造并不复杂，但方向明确，模块之间配合完整，消融实验也能说明关键模块有效。它属于“问题抓得准、改动集中、工程和方法结合较好”的论文。

一句话总结：

> FLUID 本质上是把 Block Diffusion 改得更像 AR：用严格因果注意力解决 AR checkpoint 结构错配，用 Elastic Horizon 解决固定 block 不适应文本难度的问题，再用 confidence gating 控制实际提交长度，从而在生成速度和逻辑稳定性之间取得更好的平衡。
